The mechanism

两道独立防线，协同运作

一层管「看不见」，一层管「改不动」——共同让分析与反制变得不切实际。

隐身宿主 · Stealth Host

让整个面板与数据面从探测者的视野里消失——不是隐藏，是不存在。

  • 闭式 Shadow DOM：querySelectorAll 永远查不到 UI
  • ui-guard 属性观察器：inline 隐藏写入即时回滚（≤1s）
  • 蜜罐诱饵：探测变量被触碰即上报 + 喂假数据
  • dom-heal 巡检：可见性门控，回前台立即补扫
  • loadProject 纯旁路捕获：绝不伪装 vm 实例

完整性守卫 · Integrity Guard

让每一处包装都无懈可击，每一次出网都不可复读。

  • sig-guard：存储态 bodySig 校验，篡改即隔离扣留
  • markNative 白名单：包装函数 toString 输出原生源码
  • 出网单次编码：封包处编码一次，抓包只有噪声
  • ztna 校验 + SecureVm：每次变量读写都有准入检查
  • 双通道失败必回滚：云数据与本地镜像绝不静默分叉

FAQ

常见问题

VaIMod 会被站点检测到吗？
检测的三个常用面——DOM、函数包装、网络流量——分别被闭式 Shadow DOM、markNative 白名单、单次出网编码覆盖。残余边界是 Tampermonkey 的注入时机（document-start 已是物理极限），若站点在脚本注入前就完成了全部初始化，那不是任何 userscript 能解决的。
安装后需要配置吗？
开箱即用：装好脚本打开 ccw.site，面板自动挂载。进阶玩法（本地重命名、变量锁定、value:"*" 自带检测）通过 JSON 主配置携带，见仓库 docs/配置文件说明.md。
云数据功能怎么保证不出事？
双通道（镜像 + 云端）写入，任何一条失败都不会弹「已保存」：失败即回滚本地镜像，镜像与云端永不静默分叉。另有还原点系统，改坏随时回滚。
第三方插件安全吗？
插件 html 强制消毒（剥 script/iframe/on* 等），存储条目有 bodySig 完整性校验，被篡改即隔离扣留并显示警告。但插件的 code 与页面脚本同级——导入来路不明的插件前看一眼源码，永远是好习惯。
支持哪些作品？
ccw.site 上所有含变量的作品。纯云变量项目同样完整支持（云变量可改、可锁、不可误删）；VM 未就绪时面板明确显示等待状态。
开源的，为什么还叫「防护」？
开源保护的是你的信任：每一段防御代码都可审计。防护针对的是运行时探测与篡改——探测者要面对的不是保密，而是分层反制。
